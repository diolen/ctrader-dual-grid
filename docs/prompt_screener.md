# Промпт для AI-разработчика: Создание автономного аналитического скринера на базе cTrader API

## Контекст и Цель
Необходимо создать **абсолютно новый, самостоятельный проект** (новый репозиторий), выделив его из существующего торгового движка. Цель проекта — предоставление логирования для мониторинга рынка в реальном времени. 

Проект должен **сохранить** существующее подключение к cTrader Open API и математическую/аналитическую логику стратегии Breakout Retest v3, но использовать их **исключительно для анализа** получаемых от брокера данных. 

Вся логика, не относящаяся к получению данных, их анализу и визуальному отображению, должна быть **полностью удалена**.

---

## Строгие исключения (Что необходимо удалить/не переносить)
При переносе кода из старого проекта в новый, следующие компоненты и концепции должны быть **безоговорочно удалены**:
- Любая логика исполнения сделок: отправка, модификация или отмена ордеров.
- Управление капиталом и рисками: расчет лота, position sizing, риск на сделку.
- Торговый оркестратор (Orchestrator), защитные механизмы (TradeGuard), управление устаревшими ордерами (Stale Orders).
- Модули бэктестинга и grid-оптимизации (они не нужны для runtime-скрининга).
- Любые состояния FSM, связанные с жизненным циклом сделки (например, `ENTRY_SUBMITTED`, `IN_TRADE`, `PENDING`).
- Зависимости от торговых protobuf-моделей cTrader (использовать только модели для получения свечей/котировок).

## Целевая архитектура и модули нового проекта

### 1. `config/` — Конфигурация
- **Назначение:** Хранение настроек подключения к cTrader Open API (в режиме read-only), списка отслеживаемых валютных пар и аналитических порогов стратегии (например, минимальный импульс, границы процента отката). Не содержит торговых параметров.

### 2. `connection/` — Слой взаимодействия с брокером
- **Назначение:** Асинхронное получение данных от cTrader Open API.
- **Функционал:** Инициализация соединения, аутентификация и реализация методов исключительно для запроса исторических данных (trendbars) и актуальных котировок. Любые методы, связанные с торговлей, должны быть удалены.

### 3. `core/analyzer.py` — Аналитическое ядро (бывшая стратегия v3)
- **Назначение:** Чистый анализ рыночных данных на основе логики Breakout Retest v3.
- **Функционал:** 
  - Прием потока свечей от `connection`.
  - Поиск и кластеризация ценовых уровней.
  - Детекция пробоя и расчет силы импульса (displacement).
  - Отслеживание коррекции и проверка попадания в диапазон shallow retest.
  - **Важно:** Модуль должен возвращать только аналитический статус рынка (например, DataClass с текущей фазой, ценой уровня, метриками), а не торговые сигналы или объекты ордеров.

### 4. `core/recommender.py` — Движок интерпретации
- **Назначение:** Преобразование сырых аналитических данных из `analyzer.py` в понятные текстовые выводы для трейдера.
- **Функционал:** Маппинг фаз рынка на рекомендации (например: "Поиск уровня", "Импульс, ожидание отката", "Сетап сформирован: зона подтверждения X", "Сетап упущен").

### 5. Логирование — Вывод данных
- **Назначение:** Вывод аналитических данных в реальном времени.
- **Функционал:** Реализация структурированного логирования. Должен выводить информацию: Валютная пара, Текущая цена, Текущая фаза рынка, Ключевой уровень, Текстовая рекомендация.

### 6. `main.py` — Точка входа и цикл управления
- **Назначение:** Инициализация приложения и управление асинхронным жизненным циклом.
- **Функционал:** Загрузка конфигурации, установление соединения с API, запуск циклического опроса пар, передача данных в `analyzer`, логирование и корректное завершение работы при получении сигнала выхода.

## Workflow разработки

### Этап 1: Инициализация нового проекта
- Создать структуру нового репозитория с нуля.
- Настроить минимальные зависимости, необходимые только для асинхронной работы, взаимодействия с API и отрисовки дашборда.
- Перенести из старого проекта **только** необходимые части конфигурации и модели данных (свечи), удалив все лишнее.

### Этап 2: Миграция и очистка слоя подключения
- Перенести логику подключения к cTrader Open API.
- Провести рефакторинг клиента: удалить все методы и подписки, связанные с торговлей, оставив только функционал запроса исторических и текущих свечей.

### Этап 3: Выделение и очистка аналитического ядра
- Извлечь из старой стратегии v3 математическую логику (поиск уровней, расчет импульса, проверка ретеста).
- Переписать её в `core/analyzer.py` как независимый модуль, удалив все вызовы `executor`, `orchestrator` и генерацию торговых объектов.
- Адаптировать FSM так, чтобы он описывал только фазы рыночной структуры, а не жизненный цикл ордера.

### Этап 4: Разработка системы логирования и движка рекомендаций
- Реализовать `core/recommender.py` для генерации текстовых статусов на основе выходных данных анализатора.
- Настроить структурированное логирование, обеспечивающее читаемый и обновляемый в реальном времени вывод состояния всех отслеживаемых пар.

### Этап 5: Интеграция и финальная сборка
- Связать все модули в `main.py`: Цикл "Запрос данных -> Анализ -> Логирование".
- Реализовать корректную обработку разрывов соединения и graceful shutdown.

### Этап 6: Ревизия и очистка
- Провести финальный аудит кодовой базы нового проекта. Убедиться, что в нем физически отсутствуют файлы, импорты или упоминания удаленных торговых модулей.

## Принципы проектирования

1. **Read-Only по определению:** Приложение не должно иметь технической возможности отправить торговую команду, даже гипотетически.
2. **Минимализм:** В новый проект переносится только тот код, который критически необходим для получения данных, их анализа и отображения. Всё остальное безжалостно удаляется.
3. **Детерминированность:** Аналитическое ядро должно выдавать одинаковый результат при обработке одинакового набора свечей, независимо от времени запуска.
4. **Отказоустойчивость:** Ошибка анализа или получения данных по одной валютной паре не должна приводить к падению всего приложения.

---

## Критерии приемки

- Проект представляет собой отдельный, самодостаточный репозиторий.
- При запуске `main.py` устанавливается соединение с cTrader API и в терминале выводятся обновляемые логи.
- Логирование корректно отображает аналитические фазы рынка и рекомендации, основанные на логике v3.
- В коде нового проекта полностью отсутствуют импорты или упоминания: `executor`, `orchestrator`, `position_sizer`, `trade_guard`, `backtest`, `optimize`.
- Логика получения данных от cTrader API работает стабильно и ограничена только чтением исторических и текущих свечей.
